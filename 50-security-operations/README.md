# 50 — Security Operations

> ⭐ **What this is:** detection, investigation and response — the **SC-200** half of the track, and
> the domain that answers *"we have the logs; now what?"*

**When to read it:** ⭐ **after SC-300.** The priority order for this repo is
⭐ **SC-300 → SC-200 → SC-500**, because detection without an identity model produces alerts nobody
can interpret.

**Prerequisites:** [`../30-identity-and-nhi/`](../30-identity-and-nhi/) Layers 1–5;
[`../70-operations-and-reliability/log-analytics/`](../70-operations-and-reliability/log-analytics/)
for the query surface.

---

## Why this domain exists

⭐ **Prevention fails eventually, and the value of a security team is measured in what happens
next.** This domain is the "next".

⭐ **The structural fact that organises it: the Defender products are separate sensors over one
identity plane.** Defender for Identity watches domain controllers, for Endpoint watches devices,
for Cloud Apps watches SaaS, and Entra ID Protection watches sign-ins — ⭐ **and only correlation
across them tells a story.** That correlation is what Sentinel and XDR are for.
