# 35 — Active Directory and Hybrid Identity

> ⭐ **What this is:** the on-premises half, and the machinery that joins it to the cloud.
> ⭐ **The deepest well of real-world work in this repository** — most organisations are hybrid, and
> hybrid is where the interesting failures live.

**When to read it:** ⭐ **after Layer 2** in [`../30-identity-and-nhi/`](../30-identity-and-nhi/).
⚠ **Do not skip it because it looks legacy** — a job that mentions "Entra" almost always means
"Entra *and* the AD behind it".

**Prerequisites:** [`../10-networking/dns`](../10-networking/dns/) —
⭐ **AD is a DNS-dependent system before it is anything else.**

---

## Why this domain exists

⭐ **"Is there on-premises Active Directory, and is it staying?" splits any engagement in half.**
It determines the authentication method, the source of truth, the offboarding path, the migration
type, and the blast radius of a compromise.

⭐ **And the hard security fact: the forest is the security boundary, not the domain.** Domains share
a schema and a configuration partition — ⭐ **two organisations that must not reach each other need
separate forests, not separate domains.**
