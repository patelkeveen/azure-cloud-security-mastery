# 40 — Microsoft 365 Platform

> ⭐ **What this is:** the workloads users actually touch. ⭐ **The organising insight: M365 is one
> identity and one storage substrate wearing several product names** — and end users make
> authorisation decisions at scale, every day, with no training.

**When to read it:** ⭐ after [`../30-identity-and-nhi/`](../30-identity-and-nhi/) Layers 1–3.
⭐ **Read [`exchange-online`](exchange-online/) early regardless** — it is where attacker persistence
lives.

**Prerequisites:** identity basics; [`../10-networking/dns`](../10-networking/dns/) for mail flow.

---

## Why this domain exists

⭐ **Every M365 workload is a place where a normal user can grant access to data without asking
anyone.** Sharing a file, forwarding a mailbox, adding a guest to a Team, consenting to an app — ⭐
**authorisation is delegated to end users by design**, and the security work is making those
decisions visible and bounded rather than preventing them.

⭐ **The other structural fact: a Team is not a thing.** It is an M365 group, a SharePoint site, a
chat service and a mailbox wearing one icon — which is why "migrate Teams" is four migrations.
